# Корсик 2.0

ИИ-ассистент адаптации новых сотрудников в мессенджере «МАКС» и панель для HR и руководителей внутри «МАКС» (Mini App). Решение кейса ООО «Группа ПОЛИПЛАСТИК», хакатон «Открой Моспром», 2026.

Сейчас у компании Telegram-бот «Корсик» на жёстком кнопочном сценарии. Корсик 2.0 переносит этот сценарий в «МАКС» целиком и добавляет то, чего не хватало: ответы на свободные вопросы по документам компании, разбор обратной связи, передачу проблем HR и аналитику для руководителей.

**Главный принцип: ИИ не пишет норму.** На вопрос новичка бот отвечает дословным пунктом документа с источником («ПВТР, п. 6.5.2, стр. 15»). Модель только выбирает подходящий пункт из найденных. Если ответа в документах нет, бот честно говорит «не знаю» и передаёт вопрос HR.

## Что умеет

Роли взяты из кейса.

**Новый сотрудник (бот в «МАКС»)**
- Подключается по ссылке или QR из оффера. Знакомство одним сообщением, которое меняется на месте: «ты» или «вы», согласие на сопровождение, отдельное согласие на ИИ-разбор ответов.
- Получает все 68 шагов сценария из xlsx компании по расписанию: с учётом площадки, офиса или производства, производственного календаря РФ и часового пояса. Подряд идущие шаги склеиваются, ответы на кнопки правят то же сообщение, бот не флудит.
- Задаёт любой вопрос своими словами и получает дословный пункт документа с источником и кнопкой «Связаться с HR». Личные вопросы («не пришла зарплата», «заболел») сразу уходят HR, без ИИ.
- Проходит опросы из ТЗ: 1-й и 3-й день, 2 недели, адаптационный план, 2 месяца, конец испытательного. При оценке ниже 8 или ответе «нет» бот спрашивает «что мешает?». Если опрос не пройден, напоминает на следующий рабочий день и через день.
- В первый рабочий день бот сам добавляет новичка в чаты команды. Если не пустили настройки приватности, присылает ссылки. С согласия новичка публикует его рассказ о себе в чате команды.

**HR-менеджер (панель в «МАКС» и HR-группа)**
- Список новичков по площадкам: день адаптации, этап, непройденные опросы, обращения, подключился ли.
- Заводит новичка за минуту и получает ссылку и QR для оффера.
- Обращения и красные флаги приходят в HR-группу «МАКС». HR отвечает из панели, и ответ приходит новичку в чат. Хороший ответ можно отправить в базу знаний: после подтверждения бот сам отвечает на такой вопрос.
- Обновляет базу без программиста: загружает PDF и PPTX, загружает новый xlsx сценария, в том числе с новой площадкой.

**Руководитель подразделения**
- Push «проведи встречу» на 3-й, 30-й, 60-й день и перед концом испытательного, с кнопкой «Провёл».
- Экран «Мои новички»: статус адаптации своих людей. Ответы опросов и обращения руководитель не видит.

**Руководитель HR (управление по подбору и развитию персонала)**
- Еженедельный дайджест картинкой: настроение по площадкам, средняя оценка, сигналы, зоны риска.
- Экран «Аналитика»:
  - новички в зоне риска с понятными причинами («оценка упала с 9 до 5», «нет ответа HR 2 дня»);
  - темы трудностей с динамикой и обезличенными цитатами;
  - воронка этапов адаптации.
- Срезы показываются, только если ответили 5 и больше новичков, чтобы нельзя было вычислить человека.

**Анализ обратной связи**
- Красные флаги (безопасность и охрана труда, травля, угрозы, здоровье) ловятся словарём в любом сообщении и в любом состоянии диалога. Сразу создаётся обращение и уведомление в HR-группу. Новичок получает ответ «увидит только HR» и, если нужно, номер 112.
- С согласия новичка ИИ определяет у свободного ответа тему, настроение и цитату-доказательство. Тексты о здоровье в модель не отправляются.

## Качество

Цифры получены на синтетических и эталонных данных, пересчитываются командами `make eval` и `make eval-flags`.

| Что проверяем | Результат |
|---|---|
| Верный пункт документа в первой пятёрке поиска | 50 из 50 |
| Бот ответил верным пунктом | 42 из 50 (84%) |
| Личные вопросы ушли HR без ИИ | 15 из 15 |
| Бот ответил сам, без HR (все 73 вопроса эталона) | 64% |
| Красный флаг найден (точность / полнота) | 0,96 / 0,96 |

- Эталон: 73 вопроса (50 по документам, 15 личных, 8 вне базы), подробности в [eval/RESULTS.md](eval/RESULTS.md). Пороги подобраны на этом же эталоне, поэтому цифры оптимистичные.
- Флаги: 136 синтетических ответов, [eval/flags/RESULTS.md](eval/flags/RESULTS.md).
- Автотесты: больше 650 тестов (pytest), запуск `make test`. Среди них сквозной тест: оператор производства на площадке GTP проходит весь путь от приглашения до конца испытательного срока по настоящему коду бота. Его маршрут по дням, что получили новичок, HR и руководитель, генерируется в [eval/journey/gtp-operator.md](eval/journey/gtp-operator.md).

## Данные и безопасность

- **Ответы только из документов.** Бот цитирует пункт дословно и показывает источник. Вопрос вне базы уходит HR.
- **Коммерческая тайна.** Фрагменты документов с грифом КТ в модель не отправляются.
- **Маскирование.** Перед любым вызовом модели ФИО всех сотрудников, телефоны, e-mail и номера документов заменяются метками. В журнал вызовов модели пишутся только время, тип вызова и классы данных, без текстов.
- **Согласия.** ИИ-разбор ответов идёт только с отдельного согласия новичка. Без него всё остальное работает так же.
- **Закрытый контур.** Модель переключается настройкой на локальную внутри сети компании (раздел «Режимы ИИ»). Поиск и векторизация всегда локальные.
- **Доступ к панели.** Вход только через «МАКС»: подпись `initData` проверяется по токену бота. Роль определяется по сотруднику. Руководитель видит только своих новичков, без опросов и обращений.
- **Демо-данные** синтетические и помечены. Демо-функции (машина времени) в проде выключены и не работают для живых новичков.
- **Документы заказчика** (`docs/`) — внутренние материалы, в открытый доступ не выкладываются.

## Как устроено

```
 Новичок · руководитель · HR-группа            HR · руководитель HR
          │ чат с ботом в «МАКС»                     │ Mini App в «МАКС»
          ▼                                          ▼
   Bot API «МАКС» (long polling)              Caddy, HTTPS, свой домен
          ▲                                          │ /api + initData
 ┌────────┴──────────────────────────────────────────┴────────────────┐
 │ app (Python, FastAPI): бот, планировщик, REST API                  │
 │  bot · scenario · surveys · signals · kb · tickets · chats         │
 │  manager · reports · analytics · privacy · llm                     │
 └───────┬──────────────────────┬──────────────────────┬──────────────┘
         ▼                      ▼                      ▼
  PostgreSQL + pgvector   GigaChat API или        bge-m3 (локально)
                          локальная модель
```

- Модули подключаются к боту через точки расширения (`app/bot/hooks.py`), контракты между модулями описаны в [app/CONTRACTS.md](app/CONTRACTS.md).
- Поиск по базе знаний гибридный: полнотекстовый Postgres и векторный bge-m3, объединение RRF, фильтр по площадке.
- Стек:
  - Python 3.12, FastAPI, SQLAlchemy 2, Alembic, APScheduler;
  - PostgreSQL 16 + pgvector, sentence-transformers;
  - GigaChat SDK, Playwright (картинка сводки);
  - React, Vite, TypeScript, motion (Mini App);
  - Docker Compose, Caddy.

## Запуск

Нужен Docker Desktop (на Apple Silicon образы собираются под arm64). Локально Python и Node не ставим.

```bash
cp .env.example .env        # заполнить токен бота «МАКС» и ключ GigaChat
docker compose up -d --build
make seed                   # демо-данные (все синтетические)
make import                 # сценарий из xlsx (data/raw/, в git не хранится)
make kb                     # база знаний: документы и статьи сценария с эмбеддингами
make links                  # ссылки привязки для тестовых новичков и персонала
```

- API: http://localhost:8000/health, Mini App (dev): http://localhost:5173, Postgres: `localhost:5433` (`korsik` / `korsik`).
- Миграции применяются при старте `app`; вручную — `make migrate`.
- Прочее: `make logs`, `make test`, `make eval`, `make eval-flags`, `make psql`, `make shell`, `make down`.
- API и Mini App на стенде разработки слушают только `127.0.0.1`: из локальной сети они недоступны, вход без «МАКС» работает только с этой машины.
- Чтобы не запускать long polling бота (если его уже опрашивает другой экземпляр), добавьте в `.env` строку `BOT_ENABLED=false`.

### Как показать

1. `make links` и открыть ссылку тестового новичка в «МАКС» на телефоне: пройти знакомство, задать вопрос («сколько длится обед?»), попробовать `/hr` и `/food`.
2. В панели, «Ещё» → «Демо»: перемотать тестового новичка на 1, 3, 14, 60 день или конец испытательного. Шаги и опросы этого дня придут в чат сразу.
3. Ответить на обращение из панели, ответ придёт новичку. Посмотреть «Аналитику» и сформировать сводку.

## Запуск на сервере (свой домен, HTTPS)

Нужны сервер с Docker, поддомен с A-записью на его IP и открытые порты 80 и 443.

```bash
git clone <репозиторий> && cd <каталог>
cp .env.example .env                  # токен бота, ключ GigaChat или настройки своей модели
DOMAIN=korsik.example.ru docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
docker compose exec app python -m seed.seed   # только для демо: синтетические данные
```

- Caddy (`deploy/Caddyfile`) сам получает HTTPS-сертификат и отдаёт собранную Mini App и `/api`.
- Наружу открыты только 80 и 443. База и API без прокси снаружи недоступны.
- Вход в панель только через «МАКС» (`DEV_ALLOW_NO_INIT_DATA=false`). `MINIAPP_URL` выставляется из `DOMAIN`.
- Демо-функции (машина времени, «Сформировать сводку») в проде выключены. Для показа на сервере добавьте в `.env` строку `DEMO_ENABLED=true`. Перематывать можно только тестовых и синтетических новичков.
- Адрес `https://<DOMAIN>` один раз прописывается у бота на business.max.ru (подробно — `miniapp/README.md`).

## Режимы ИИ: облако или закрытый контур

ИИ в решении делает две небольшие задачи: выбирает подходящий пункт из пяти найденных и разбирает свободные ответы в опросах. Поиск по документам, векторизация (bge-m3), правила личных вопросов и красных флагов работают локально в любом режиме. Если модель недоступна, бот всё равно работает: при уверенном поиске отвечает пунктом сам, иначе передаёт вопрос HR.

Режим выбирается в `.env`:

| Режим | Настройки |
|---|---|
| Облако, GigaChat API (по умолчанию) | `LLM_PROVIDER=gigachat`, `GIGACHAT_CREDENTIALS`, `GIGACHAT_SCOPE`, `GIGACHAT_MODEL` |
| Закрытый контур, своя модель | `LLM_PROVIDER=openai`, `LLM_BASE_URL=http://<сервер модели>/v1`, `LLM_MODEL=<имя модели>`, при необходимости `LLM_API_KEY` |

Во втором режиме подходит любой сервер с OpenAI-совместимым API внутри сети компании, например vLLM или Ollama с открытой моделью. Персональные данные маскируются перед любым вызовом модели, документы с грифом коммерческой тайны в модель не отправляются.

Без доступа в интернет:
- модель эмбеддингов кладётся в том `models` заранее (один раз запустить `make kb` там, где есть интернет, и перенести том) или указывается локальный путь: `EMBEDDING_MODEL=/models/bge-m3`;
- в `.env` добавить `HF_HUB_OFFLINE=1`, чтобы приложение не обращалось к HuggingFace;
- наружу остаётся только Bot API «МАКС»: без него мессенджер не работает.
