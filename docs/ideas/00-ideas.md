# Идеи — рабочий свод (ветка Ивана)

Статус: черновик штурма, 23.10. Дополняется по мере разведки (`research/01–07`).
Потом сводим с идеями второй ветки.

## Рамка: не рассыльщик, а система раннего предупреждения

Старый «Корсик» шлёт сообщения по расписанию и узнаёт об уходе новичка по факту
увольнения. Новый замечает, что человек «поплыл», за недели до заявления, и запускает
действие. Аргумент окупаемости: каждый уход на испытательном сроке = потерянные
подбор + обучение.

Базовый набор (бот в МАКС + RAG + sentiment + дашборд) принесут все — это просто
перечень из кейса. Выигрывает идея продукта поверх него.

## Три цикла

### 1. Новичок: ответ с источником или честная передача человеку
- Ответ только со ссылкой на пункт документа; нет источника — так и говорим и зовём
  рекрутера.
- Рекрутер отвечает через того же бота (ретрансляция): новичок не уходит в другой чат,
  история не теряется.
- Рекрутер получает черновик ответа из базы знаний и только правит — это и есть «−70 %
  рутины».

### 2. Сигналы: опрос-беседа вместо анкеты (главная новаторская фишка)
- Вместо кнопок и шкал 1–10 — один живой вопрос + уточнение («а что именно мешает?»).
  ИИ раскладывает ответ в те же поля анкеты — метрики HR сохраняются.
- Тревожный сигнал → карточка HR: что сказал, какая проблема, что предлагается сделать.
- Руководителю — подсказка к встрече 1:1 («новичок не понимает задачи — спроси вот
  это») без цитаты: новичку безопасно говорить честно.
- Флаг ведётся до закрытия, а не «отправлен и забыт».

### 3. База знаний учится сама
- Неотвеченные вопросы → список «дыры в базе» для HR с черновиком статьи →
  утверждение одним нажатием → бот знает ответ.

## Платформа и тиражирование
- Их xlsx-сценарий загружается как есть; HR правит таблицу — бот меняется. Новая дочка
  = новая таблица. Закрывает «масштабирование требует разработчиков» и «типовой продукт
  для крупных корпораций».

## Фишки под завод
- Голосовые сообщения: рабочему в цеху в перчатках проще наговорить, чем печатать.

## Отложенные вопросы к обсуждению
1. Рамка «раннее предупреждение» — главная или ищем другую?
2. Опрос-беседа — не будет ли воспринята как «HR теряет контроль над вопросами»?
3. Голос и подсказки руководителю — в идею или в запас?

## Из разведки (дополняется)

### 02 — рынок и аналоги (`02-market-analogs.md`)
**Что подтверждает рамку**
- В РФ никто не собирает в одном продукте «sentiment открытых ответов + красные
  флаги + нудж руководителю + дайджест». На Западе это три разных класса продуктов:
  Leena/Moveworks (ответы), Peakon/Glint/Culture Amp (комментарии и риск ухода),
  Enboarder/Humu (нуджи руководителю). Мы собираем их в одном боте.
- HR-решений в МАКС не найдено — ниша свободна. МАКС: 18,2 млн DAU (10.2025),
  > 77 млн (03.2026).
- Боль в цифрах (hh.ru): 40 % новичков думали уволиться в первые месяцы, из них у
  58 % причина «ожидания ≠ реальность»; у 22 % работодателей до 30 % новичков уходят
  за 3 месяца (2025).
- Gallup: при активном участии руководителя шанс на отличный онбординг ×3,4 →
  нудж руководителю обоснован цифрой.
- Новичкам нужны люди: 72 % хотят наставника, приложение выбирают 14 % → подача
  «бот подталкивает людей к людям», а не «бот вместо HR».
- Норникель: бот адаптации для рабочих без ПК, > 2000 пользователей в первый год,
  из них 600 рабочих (2021). Других публичных ИИ-кейсов у промышленников не нашли.
- Тиражирование: у ПОЛИПЛАСТИКа 33 завода и 46 торговых домов (hh.ru); в Москве
  4,5 тыс. промпредприятий и > 750 тыс. занятых.
- Осторожно: Brandon Hall (+82 % удержания) и «замена = 50–200 % зарплаты» —
  только пересказы. На слайды — Gallup и hh.ru.

**Что берём в идею**
- Нудж мастеру — одно действие в мессенджере («встреча с Ивановым сегодня, вот
  3 вопроса»), а не ссылка на дашборд. Метрика «нуджи выполнены» — опережающая,
  видна сразу, в отличие от удержания через 90 дней.
- Порог конфиденциальности: нет цитат и сводки, если в группе < 5 ответов
  (бригада из 4 = деанонимизация).
- Сравнение настроений между площадками и сменами — 33 завода.
- Пульс «совпало ли с обещанным?» на 7-й и 30-й день — бьёт в главную причину ухода.
- Pre-boarding от оффера: фото проходной, СИЗ, маршрут, контакт мастера.
- «Вы сказали — мы сделали»: бот сообщает новичкам, что изменили по их ответам.
- Мини-тест по загруженному регламенту (ТБ, СИЗ) — HR загрузил PDF, получил и
  ответы, и проверку усвоения.
- KPI пилота как обязательство: «≥ 60 % вопросов без HR».

### 01 — платформа МАКС (`01-max-platform.md`)
**Срочно (оргриск):** бота в МАКС заводит только верифицированная организация /
ИП / самозанятый — резидент РФ; модерация до 48 рабочих часов. Регистрировать сегодня
+ параллельно мок API по OpenAPI-схеме, чтобы демо не зависело от модерации.

**Что подтверждает идею**
- Чат «новичок + рекрутер» бот создать не может → наша ретрансляция через бота —
  единственный бесшовный путь: бот — админ HR-группы, публикует карточку тикета,
  ответ рекрутера (reply) уходит новичку от имени бота.
- Мини-приложения есть (`open_app`, подписанный `initData`) → дашборд руководителя и
  консоль HR прямо внутри МАКС, без отдельного портала.
- Отложенной отправки в API нет → свой планировщик таймлайна (это и есть «CRON» из
  требований); очередь с лимитом 30 rps на бота, 2 сообщения/с в диалог.
- Старт только от новичка → QR на оффере `max.ru/<bot>?start=<token>`: токен сразу
  привязывает человека к площадке и дате выхода.
- Только inline-кнопки, нативных опросов нет → шкалу 1–10 делаем кнопками; опрос-беседа
  здесь ещё и естественнее анкеты.
- PDF как файл (до 4 ГБ), картинки до 50 МБ — карты территорий и памятки ложатся.
- SDK: `maxapi` (aiogram-стиль, FSM, webhook на FastAPI).

### 03 — победители, open-source, техники (`03-winners-opensource-ideas.md`)
- Публичных победителей с таким же кейсом нет. Мини-тест по PDF, геймификация и
  автоплан онбординга уже были у призёров «Цифрового прорыва» (ПСБ) → **не новаторство**.
- Как выигрывают (True Tech Hack): один модуль, доведённый до конца, лучше трёх
  недоделанных; понятные точки вмешательства человека; цифры качества.
- Стек: тонкий свой RAG (FastAPI + pgvector/Qdrant, `deepvk/USER-bge-m3`,
  `bge-reranker-v2-m3`), без тяжёлых платформ (Dify, RAGFlow). Приёмы победителя
  RAG Challenge: строгая схема ответа с полем страниц, роутинг по типу вопроса.
- Флаги: словарь триггеров + быстрые ru-модели + LLM по таксономии; каждый флаг
  обязан привести дословную цитату (проверяется кодом). Отдельный флаг — охрана труда.
- Галлюцинации: роутер намерений (кадровое и юридическое → HR без генерации), порог
  реранкера → отказ, проверка, что цитата дословно есть в найденном фрагменте.
  Метрики: верность источнику, точность цитат, верные/лишние отказы, полнота эскалации.
- Риск ухода: объяснимый балльный индекс по поведению (пропуск опроса, падение оценок,
  флаги, неподтверждённая встреча 1:1) с «почему» и «что сделать»; HR отмечает
  «верно / ложно». Повод для разговора, а не решение (152-ФЗ, ст. 16).

### 04–07 — сценарий «Корсика» и база знаний
**Аудит их сценария — готовый слайд «мы разобрали ваш бот»** (`04-scenario-map.md`)
- 68 сообщений, 55 обязательных; 27 временных слотов + 2 событийных триггера; первый
  день — 9 касаний с 10:00 до 18:00.
- Свободный текст уходит в никуда: на любой вопрос — заглушка «посоветуюсь с
  коллегами»; ещё в 7 местах окно «укажите причину», но не описано, кто это читает.
  Это и есть «40 % времени HR».
- ~31 вопрос в опросах, 16 по шкале 1–10; порог «ниже 8» срабатывает почти всегда →
  «опрос на 1–2 минуты» не выполняется.
- Между 2-й неделей и ~52-м днём пульса нет — **окно тишины ~5 недель**.
- **Руководитель не получает ни одного сообщения**; «нет доступов в первый день» →
  совет «уточни у руководителя», без заявки и сигнала.
- Два ключевых сообщения (самопрезентация, план адаптации) — «по отмашке рекрутера»,
  вручную.
- Спрашивают «ты / вы», но текстов на «вы» нет; пол не учитывается; испытательный
  жёстко 3 мес., хотя по ПВТР сдвигается на больничный (п. 6.1.10), у руководителей —
  до 6 мес. (п. 6.1.9).
- Персонализация фактически двухосевая: офис (GrPP, Luzhniki) / завод (GTP).
  Гипотеза: GrPP — головной офис (Очаковское ш., 18), GTP — завод «Газтрубпласт»,
  Luzhniki — отдельный офис. **Подтвердить на чекпоинте.**

**База знаний** (`05-knowledge-base.md`, ПВТР распознан полностью)
- Правила закрыты хорошо, с пунктом и страницей: режим, зарплата 29-го и 14-го,
  отпуск, больничный, подарок до 3 000 ₽, горячая линия 4384.
- Быт первой недели не закрыт: транспорт, столовая, пропуск, IT-доступы, ДМС,
  спецодежда, справки. Из ~25 типовых тем полностью ~10, частично ~5 → прямой
  довод за «пробелы базы знаний» и загрузку документов HR без кода.
- Антикоррупция и КТ — выжимки, полный текст «на портале»; у портала уже есть разделы
  «Столовая», «Мои заявки», «Бланки» → источник для базы знаний.

**Данные для демо и метрик:** `06-golden-set.jsonl` — 73 вопроса (50 отвечаемых,
15 эскалаций, 8 вне базы); `07-survey-answers-synth.jsonl` — 120 синтетических
ответов, 43 с флагами (сарказм, скрытые сигналы).

**Новые идеи отсюда**
- **Аудит сценария как функция продукта**: загрузил xlsx → получил «окна тишины»,
  руководитель без касаний, ветки без действия. На чекпоинте показываем на их файле.
- Ветка «нет доступов» → сразу заявка/сигнал руководителю и IT, а не совет.
- «Отмашку рекрутера» заменить событием (руководитель нажал «план готов»).
- Испытательный срок считается по ПВТР (больничный, руководители — 6 мес.).

## Второй заход: психология адаптации (ссылки проверяются в `08-psychology-factcheck.md`)

### Научный скелет вместо «опросов от балды»
- **Три показателя адаптации по Т. Бауэр**: ясность роли, уверенность в себе,
  принятие в коллективе — именно они предсказывают, останется ли человек
  (метаанализ JAP 2007, 70 выборок, N = 12 279; связь с намерением остаться
  r = 0,23 / 0,15 / 0,24 — умеренная, на слайде без преувеличений). Опрос-беседа
  и флаги меряют эти три оси, а не набор случайных вопросов. «Индекс адаптации» =
  три шкалы по каждому новичку и по площадке.
- Модель 4C (Compliance, Clarification, Culture, Connection): текущий «Корсик» почти
  весь про Compliance; Clarification и Connection провалены — показать на их сценарии.

### Инсайты → фичи
1. **Бот молчит, когда новичку хуже всего.** ~~спад на 3–8 неделе~~ — НЕ подтверждено.
   Подтверждено (Kammeyer-Mueller 2013, 264 новичка, 14 еженедельных замеров):
   поддержка коллег и руководителя и настроение новичка падают сильнее всего в
   начале; новичок, которого подрывает руководитель, уходит быстрее (отношение рисков
   3,01). Подача: «окно тишины ~5 недель приходится на период, когда поддержка падает»
   + «руководитель — главный фактор» (это же обоснование нуджа).
2. **Шок реальности = главная причина ухода** (58 % — ожидания ≠ реальность, hh.ru).
   Ответ — честное превью первой смены до выхода. Эффект превью в науке малый
   (r ≈ −0,06…−0,10, после найма −0,10) → подавать как гигиену, не как прорыв.
3. **Страх задать глупый вопрос.** Бот — безопасное место для неловких вопросов. А что
   новички спрашивают у бота, но не у людей, — агрегированный сигнал о том, где
   руководителям надо объяснять лучше.
4. **Прямой вопрос «планируешь остаться?» под именем даёт враньё** (социальная
   желательность). Косвенный вопрос «что бы ты посоветовал другу, который к нам
   устраивается?» + поведенческие сигналы честнее.
5. **Эффект наблюдения.** Если новичок узнает, что его тексты анализируют и
   пересылают, он перестанет быть честным, и вся аналитика умрёт. Нужны прозрачность и
   выбор: безопасность и травля — эскалация автоматически; остальное — «передать HR?
   анонимно / с именем / нет». Бот прямо говорит, кто что увидит.
6. **Пик–конец.** Человек запоминает пик и финал. Сейчас финал — «наше общение подошло
   к концу», и бот исчезает. Вместо этого — **«из новичка в проводники»**: после
   испытательного бот предлагает стать бадди следующему новичку на площадке. Замкнутый
   цикл Connection + бесплатный источник наставников.
7. **Перегруз первого дня.** 9 касаний с 10:00 до 18:00 — информационный перегруз;
   выдавать «точно вовремя», остальное по запросу. Правила ОТ — интервальное повторение
   (3-й, 10-й, 30-й день, один вопрос), а не разовый тест.
8. **Руководителя тоже надо адаптировать.** За 2 дня до выхода бот спрашивает
   руководителя и IT: рабочее место, доступы, наставник назначен? Светофор готовности.
   Проблема «нет доступов в первый день» ловится до первого дня, а не через 2 недели.
9. **Тон.** «Привет-привет-привет! 🐾» для офисного новичка нормально, для 45-летнего
   сварщика — нет. LLM переписывает тексты сценария на «вы», в нужный род, коротко для
   цеха — закрывает дыру «спрашиваем ты/вы, а текстов на вы нет» и требование
   «корпоративный стиль».
10. **Метрика-ориентир** — не «% вопросов, закрытых ботом», а «сколько человеческих
    контактов случилось благодаря боту» (встречи 1:1, знакомство с наставником,
    закрытые флаги).

### Цифры из фактчека, годные для слайдов (`08-psychology-factcheck.md`)
- Retrieval practice (Roediger & Karpicke 2006): через неделю 61 % при самопроверке
  против 40 % при перечитывании → повторение правил ОТ вопросами, а не памяткой.
- Milliken 2003: 85 % сотрудников хоть раз промолчали о важной проблеме, главная
  причина — страх ярлыка → бот как место для неловких вопросов.
- Morrison 1993: чем чаще новичок спрашивает, тем лучше адаптируется.
- Microsoft, бадди (HBR 2019, самоотчёт, пилот 600 чел.): 56 % встречавшихся с бадди
  хоть раз сказали, что он ускорил выход на продуктивность; при 8+ встречах — 97 %.
  Не писать «97 % стали продуктивнее».
- Пик–конец (Kahneman 1993) подтверждён; перенос на онбординг — наш тезис.
- Мониторинг на работе: удовлетворённость r = −0,09 — эффект слежки есть, но
  умеренный; исследований про рабочие чаты нет.

### Возражения, которые надо снять заранее
- Телефоны в цеху часто запрещены правилами ОТ → рассылки по графику смен (тихие
  часы), голосовые — в перерыв. Спросить у заказчика.
- Не у всех рабочих есть МАКС и смартфон → запасной канал (QR-киоск в комнате
  отдыха). Спросить.
- «−70 % рутины HR» — обещание кейса, не наше. Показываем свою измеренную цифру
  (счётчик часов), а не повторяем 70 %.
- Индекс риска не должен стать «чёрным списком» руководителя: видит только HR,
  руководителю — действие («проведи встречу»), не балл.

## Третий заход: интерфейсы и база знаний (обсуждение с Иваном, 23.10)

### Интерфейсы — у каждой роли свой экран
- Новичок: **бот** (основное) + **мини-приложение** «приборная панель»: «Мой путь»
  (день N из 90, чек-лист первых дней), просмотр документа с подсветкой цитируемого
  пункта (кнопка из ответа бота), «Моя команда», карта площадки.
- Руководитель: **мини-приложение в МАКС** — новички со светофором по трём осям,
  дела на сегодня («встреча с Ивановым, 3 вопроса» + «Провёл»), готовность до выхода.
  Балл риска не видит.
- HR: **веб-платформа** — входящие сигналы (новый → в работе → закрыт), диалоги
  эскалации (ответ уходит через бота; дубль — HR-группа в МАКС), база знаний (загрузка,
  дыры, черновики, отчёт качества), сценарий (импорт xlsx, таймлайн, аудит), аналитика.
- Руководитель подбора: **картинка-отчёт раз в неделю в МАКС** (как статистика в
  панели Remnawave): новички, настроение по площадкам, топ-3 проблемы, закрытые
  сигналы, сэкономленные часы. Руководителям — своя карточка по их людям. Раз в месяц —
  PDF. Рендер HTML → PNG на сервере.
- Веб и мини-приложение — **одно приложение** с ролями: из МАКС вход по подписанному
  initData, из браузера — по логину.

### База знаний — свой конвейер из промышленных компонентов
Не с нуля и не готовая платформа (RAGFlow/Dify/Onyx: тяжёлые, мешают «контракту»
цитата-или-эскалация, бьют по новаторству).
- Разбор: Docling — PDF, DOCX, PPTX, XLSX, HTML, сканы со встроенным OCR → структура.
- Нарезка по пунктам регламента, путь «документ → раздел → пункт».
- Метаданные: площадка, тип, версия, дата действия → сначала фильтр, потом поиск.
- Гибридный поиск: лексический + плотный (bge-m3 умеет оба) → реранкер.
- Contextual retrieval: ИИ дописывает к куску контекст перед индексацией
  (−49 % промахов, −67 % с реранкером — по их замерам).
- Расширение до раздела; версии — старая редакция не отвечает.
- **Контроль качества как фича**: после каждой загрузки автопрогон golden set →
  отчёт HR (точность, лишние отказы, эскалации). Это и есть доказательство «не
  деградирует».
- Поиск противоречий нового документа со старыми.
- Хранилище: Postgres (pgvector + полнотекст) или Qdrant (гибрид из коробки) — решить
  на спеке.

Открыто: схема «бот + одно веб-приложение» — ок?; HR в демо — веб + группа МАКС?;
модель ИИ — облачная российская или локальная?

## Рейтинг идей (сводный, черновик)

### Ядро — закрывает задачи кейса, без него нет прототипа
1. Бот в МАКС, таймлайн из **их xlsx как есть** + персонализация по площадкам (QR на
   оффере задаёт площадку и дату выхода).
2. Ответ с пальцем на пункт документа (кнопка «открыть PDF на странице») или честный
   отказ → эскалация.
3. Эскалация-ретрансляция: рекрутер отвечает в HR-группе, новичок — в том же окне;
   рекрутер видит черновик ответа с цитатами (copilot HR).
4. Флаги с цитатой → карточка HR → флаг ведётся до закрытия.
5. Мини-приложение в МАКС: кабинет HR (загрузка PDF без кода) и дашборд руководителя.
