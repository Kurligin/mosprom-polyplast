# 01. Платформа MAX для ботов: техразведка (на 23.10.2026)

Кейс: «Корсик» ПОЛИПЛАСТИК, перенос из Telegram в MAX. Ссылки на источники даны как [n], список в конце.
Главный источник истины здесь официальная OpenAPI-схема `max-messenger/api-schema` (v0.0.33, коммит от 18.09.2026) [5]. Её сверяли с dev.max.ru и с исходниками официальных SDK.

## TL;DR для архитектуры

1. **Встроенного планировщика в Bot API нет.** В `POST /messages` нет поля времени отправки, во всей схеме тоже ничего подобного [2][5]. CRON-таймлайн (−3 дня, день 1 по часам, 3 день, 2 недели, месяц, 2 месяца, конец ИС) строим у себя: APScheduler или Celery beat плюс таблица `scheduled_touchpoints` в БД. Темп отправки ограничен: 30 rps на бота и 2 сообщения в секунду в один диалог [2][4]. Нужна очередь с троттлингом.
2. **Новичок должен сам запустить бота.** Ботом это делается deep-link'ом `https://max.ru/<bot>?start=<payload>` (до 128 символов) в QR на оффере. Payload приходит в `bot_started` [5]. В payload кладём одноразовый токен онбординга (кто, площадка GrPP/GTP/Luzhniki, дата выхода) и связываем `user_id` MAX с карточкой сотрудника. Может ли бот написать первым пользователю, который бота не запускал, документация прямо не говорит (**не подтверждено**). На это не опираемся.
3. **«Бесшовную эскалацию» через создание чата API не поддерживает.** Метода создания чата нет [1][5]. Кнопка `chat` убрана из схемы и SDK [5][7]. `POST /chats/{id}/members` **ограничен с 09.09.2026**, детали не раскрыты [1][3]. Надёжный вариант: **бот-ретранслятор**. Бот (админ) сидит в групповом HR-чате, пересылает туда сообщения новичка через `link: {type: forward}` с карточкой тикета, ответ рекрутера (reply в HR-чате) бот отправляет новичку от своего имени. Запасные пути: «HR-консоль» в мини-приложении и кнопка `link` на профиль рекрутера.
4. **Webhook обязателен для прода.** Long polling «не подходит для production» [4][5]. Webhook работает только по HTTPS на порту 443 с сертификатом доверенного УЦ (в том числе Минцифры), self-signed не принимается. Проверка идёт по заголовку `X-Max-Bot-Api-Secret`, ретраи длятся до 8 часов [4][5]. На демо годится long polling, но в презентации показываем webhook.
5. **Интерактив почти как в Telegram, но всё inline.** Кнопки: `callback`, `link`, `message`, `request_contact`, `request_geo_location`, `open_app`, `clipboard` [5]. Reply-клавиатуры нет (не документирована) [11], нативных опросов (poll) нет [11]. Шкалу 1–10 делаем из callback-кнопок (2 ряда по 5), после ответа сообщение редактируется одним `POST /answers` с уведомлением [5][7][11].
6. **Вложения подходят под требования кейса.** PDF-карта отправляется как `file` (до 4 ГБ), картинки как `image` (до 50 МБ). Загрузка в 3 шага: `POST /uploads` → URL → multipart → token. Сразу после загрузки файл может быть «не готов» (ошибка 400), такую отправку ретраим [5]. Токены загруженных PDF кэшируем, чтобы не загружать файл каждому новичку.
7. **Мини-приложения есть, и это готовый дашборд HR и руководителя внутри MAX.** Открываются кнопкой `open_app` или ссылкой `max.ru/<bot>?startapp=<payload>`. `initData` подписан HMAC-SHA256 по той же схеме, что в Telegram (secret = HMAC("WebAppData", bot_token)) [8][9].
8. **Оргриск на хакатоне.** Бота может создать только верифицированная организация, ИП или самозанятый, резидент РФ. Лимит: 5 ботов на организацию или ИП, 2 на самозанятого. **Модерация занимает до 48 рабочих часов** [4][10]. Бота нужно заводить немедленно (от ИП или самозанятого кого-то из команды), иначе демо пойдёт на моке API.

## 1. Bot API: создание, транспорт, отправка, лимиты, форматирование

- **Создание бота.** Через платформу партнёров business.max.ru/self или мини-приложение «MAX для бизнеса» [10]. Требуется верифицированный профиль организации, ИП или самозанятого, резидента РФ [4][10]. Верификация идёт через Госуслуги (роль «Руководитель» или «Администратор») либо T-Business ID / Alfa ID [12]. Лимит: 5 ботов на организацию или ИП, 2 на самозанятого. Ник генерируется автоматически: `idИНН_bot`. Модерация до 48 рабочих часов, до её прохождения пользователи бота не видят [4][10]. README TS-SDK ещё упоминает Master Bot (`max.ru/masterbot`) [7], но официальная страница создания его не упоминает [10]. Считаем, что актуален путь через business.max.ru.
- **Хост и авторизация.** Хост `https://platform-api2.max.ru`, токен передаётся в заголовке `Authorization: <token>`. Токен в query больше не принимается [1][5].
- **Получение событий.** Webhook (`POST /subscriptions`: `url`, `secret` → заголовок `X-Max-Bot-Api-Secret`, `update_types`) или long polling (`GET /updates`, минимум 300 мс). Одновременно оба способа использовать нельзя. Long polling не для прода [4][5]. Webhook: порт 443, только HTTPS, доверенный УЦ, ретраи до 8 ч [4][5]. По данным vc.ru, если сервер 8 часов не отвечает 200, бот отписывается от webhook [11] (официально **не подтверждено**).
- **События** [5][7]: `bot_started` (с payload), `bot_stopped`, `bot_added`/`bot_removed`, `message_created`, `message_edited`, `message_removed`, `message_callback`, `user_added`/`user_removed`, `chat_title_changed`, `dialog_muted`/`unmuted`/`cleared`/`removed`, `comment_*`. В maxapi есть ещё `bot_admin_permissions_changed` и `message_chat_created` [13].
- **Отправка.** `POST /messages?user_id=…|chat_id=…`. Тело: `text` (до 4000 символов), `attachments[]`, `link` (`reply`/`forward` + `mid`), `notify` (false = без пуша), `format` (`markdown`/`html`) [2][5]. Правка: `PUT /messages?message_id=` (`attachments: []` удаляет вложения, `null` оставляет как есть) [5]. Удаление: `DELETE /messages`. Чтение: `GET /messages`, `GET /messages/{id}` [1]. Индикатор «печатает»: `POST /chats/{id}/actions` [1].
- **Лимиты.** 30 rps на хост [4]. Не больше 2 сообщений в секунду в один диалог, чат или канал, то же для `/answers` [2]. При превышении 429 [5]. Команд в меню до 32, имя до 64 символов, описание до 128 [5].
- **Форматирование** [5]. Markdown: `*i*`, `**b**`, `~~s~~`, `++u++`, `` `code` ``, `^^highlight^^`, `> quote`, `[text](url)`, `[name](max://user/<id>)`, `# H`. HTML: `<b> <i> <s> <u> <a> <code>/<pre> <mark> <blockquote> <h1>`, остальные теги вырезаются. Работает на iOS 3.1+ и Android 2.20.0+.

## 2. Интерактив и вложения

- **Кнопки** (`inline_keyboard`, двумерный массив `payload.buttons`) [5]:
  - `callback` (payload до 1024) → событие `message_callback`;
  - `link` (url до 2048);
  - `message`: отправляет в чат текст кнопки от имени пользователя (аналог reply-клавиатуры Telegram);
  - `request_contact`: присылает VCF [7];
  - `request_geo_location` (`quick` — без подтверждения);
  - `open_app` (`web_app`, `contact_id`, payload до 512, `[\w-]`);
  - `clipboard` (payload до 1024).
  
  Текст кнопки до 128 символов [5].
- **Лимиты клавиатуры** в официальной схеме не указаны. Сторонние источники называют 210 кнопок, 30 рядов, до 7 в ряду [6][11] (официально **не подтверждено**).
- **Кнопки `chat`** (бот создаёт чат с пользователем) в схеме v0.0.33 и в коде TS/Go SDK нет. Описание осталось только в устаревшем `docs/04-keyboard.md` TS-SDK [5][7]. Считаем, что её **нет**.
- **Ответ на callback.** `POST /answers?callback_id=`: тело `message` (заменить сообщение с кнопками) и/или `notification` (одноразовое уведомление) [5][7]. Это один вызов вместо пары answerCallbackQuery + editMessageText [11]. Срок жизни `callback_id` **не подтверждён**.
- **Вложения** [2][5]: `image`, `video`, `audio`, `file`, `sticker`, `contact`, `inline_keyboard`, `share` (URL-превью), `location`.
- **Загрузка** [5]: `POST /uploads?type=image|video|audio|file` → `{url}` → multipart `data=@file` → `{token}` → `{"type":"file","payload":{"token":…}}`. Лимиты: image до 50 МБ и 7680×7680 (JPG/PNG/GIF/TIFF/BMP/HEIC), video до 250 МБ, audio до 256 МБ или 60 мин, file (PDF и др.) до 4 ГБ. Один файл на запрос. Есть resumable-загрузка через `Content-Range`. `type=photo` устарел.
- **Правка и удаление** работают только для сообщений младше 24 ч [11] (сторонний источник, в схеме срок **не найден**).

## 3. Планировщик и инициация диалога

- **Отложенной отправки в Bot API нет.** В `NewMessageBody` нет поля времени, в схеме нет методов scheduling [2][5]. Требование кейса «поддержка CRON» реализуем у себя:
  - APScheduler (AsyncIOScheduler + SQLAlchemyJobStore на Postgres), этого хватает для MVP; Celery beat + Redis, если нужен горизонтальный масштаб;
  - таблица `touchpoints(employee_id, step, due_at, status, attempts)`, событие = отправка в очередь, воркер с токен-бакетом (≤ 25 rps на бота, ≤ 2 msg/s на диалог);
  - время отправки считается в часовом поясе площадки, «день 1 по часам» строится от `start_date`.
- **Инициация.** Бот получает `chat_id` диалога в `bot_started`. Отправка по `user_id` возможна [5], но `403 chat.denied` возникает, «когда пользователь остановил бота или у бота нет доступа к чату» [5]. Возможность написать человеку, который не нажимал «Начать», **не подтверждена**. Сторонние гайды трактуют рассылки без согласия как спам [14]. Решение: оффер или письмо с QR → `?start=<one-time-token>`. Обрабатываем `bot_stopped`: помечаем сотрудника и уведомляем HR.

## 4. Групповые чаты и эскалация живому рекрутеру

Что есть в API [1][5]:
- `GET/PATCH /chats/{id}`, участники (`GET/POST/DELETE /chats/{id}/members`), админы, пины, `actions`;
- бот может быть админом группового чата;
- `POST /chats/{id}/members` добавляет до 100 `user_ids`, если у бота есть право `add_remove_members` [3]. Но **с 09.09.2026 метод «ограничен»** [1][3], и как именно, не раскрыто;
- `GET /chats` (список чатов) не поддерживается с июня 2026 [1].

Метода создания чата нет [1][5].

Варианты для «бесшовной эскалации»:

| Вариант | Реализуемость | Комментарий |
|---|---|---|
| A. Бот создаёт чат «новичок + рекрутер» | **Нет** | Нет метода создания чата и кнопки `chat`, добавление участников ограничено [1][3][5] |
| B. **Бот-ретранслятор (рекомендуется)** | Да, только документированные методы | HR-группа заводится вручную, бот в ней админ. Эскалация: бот публикует карточку тикета (ФИО, площадка, день адаптации, sentiment, последние N сообщений, кнопки «Взять», «Закрыть») и пересылает сообщение новичка (`link.type=forward`). Рекрутер отвечает reply'ем, бот по `mid` находит тикет и шлёт ответ новичку: «Анна (HR): …». Новичок остаётся в одном диалоге, контекст не теряется |
| C. HR-консоль в Mini App / веб | Да | Тот же тикет-сервис, но рекрутер отвечает из мини-приложения. Ответ уходит через `POST /messages` |
| D. Ссылка на личный профиль рекрутера | Частично | Кнопка `link` на публичную ссылку профиля или вложение `contact`. Формат ссылки на профиль пользователя **не подтверждён**. Это «шов»: контекст не переносится, бот диалог не видит |

Для демо выбираем B (+C как витрину). Это и есть «эскалация через API МАКС»: бот держит оба конца, логирует переписку для аналитики и для режима «AI молчит, пока тикет открыт».

## 5. Мини-приложения (WebApp)

- Работают только внутри бота: кнопка запуска в чате, кнопка `open_app` или ссылка `https://max.ru/<botName>?startapp=<payload>`. Payload до 512 символов, только `[A-Za-z0-9_-]`, доступен как `initDataUnsafe.start_param` [8].
- Хостинг свой, только HTTPS, URL до 1024 символов [8]. Подключаются в настройках бота, доступны тем же категориям (юрлица, ИП, самозанятые РФ) [8].
- `window.WebApp.initData` (`WebAppData`) содержит `user`, `chat`, `auth_date`, `query_id`, `hash`. Проверка: `secret_key = HMAC_SHA256(key="WebAppData", msg=bot_token)`, затем `hash == hex(HMAC_SHA256(secret_key, sorted "k=v\n…"))` [9]. Схема идентична Telegram, срок годности `auth_date` проверяем сами [9].
- MAX Bridge (`/docs/webapps/bridge`) и UI-кит MAX UI (`github.com/max-messenger/max-ui`, ★67, коммит от 22.10.2026) [12][15]. Хватит на дашборд HR/руководителя: список новичков по площадкам, красные флаги, открытые тикеты.

**Рекомендация для Python: `maxapi`.** Это самый живой и популярный Python-SDK. API в стиле aiogram сокращает перенос логики «Корсика» с Telegram. ## 7. Корпоративная сторона

- **«MAX для бизнеса» (платформа партнёров)** даёт чат-боты, мини-приложения, каналы и «Цифровой ID» (последний только юрлицам и ИП). Верификация через Госуслуги или банки, только резиденты РФ [12]. Поддержка: `partner_support@max.ru` [12].
- **Лицензии сотрудников.** По данным Forbes в пересказе «Кода Дурова» (июнь 2026), сотрудники, которые ведут переписку с клиентами от имени компании, активируют лицензию через корпоративный номер. В презентации VK фигурировали цены 1517–2333 ₽ за лицензию, на старте обещано бесплатно [17]. Это слухи и презентация, официально **не подтверждено**.
- **Статус.** MAX включён в реестр российского ПО [18]. Минтруд обсуждает использование MAX в кадровом документообороте как возможность, а не обязанность [17].
- **152-ФЗ.** Официального документа MAX о хранении ПДн бизнес-ботов не нашли. Тезис «соответствует 152-ФЗ» встречается только в маркетинговых статьях [18] (**не подтверждено**). Для архитектуры: оператор ПДн — ПОЛИПЛАСТИК. ПДн новичков (ФИО, площадка, ответы опросов, sentiment) храним в своей БД в РФ, в MAX уходят только тексты сообщений. LLM нужна on-prem или российская (GigaChat, YandexGPT) либо обезличивание перед внешней моделью. Согласие на обработку берём кнопкой при первом старте.
- **Кейсы переноса HR-ботов из Telegram в MAX.** Публичных кейсов с названием компании не нашли. Есть кейс студии Workspace «HR-ассистент в MAX: найм, адаптация» (на этапе приёмки, без имени заказчика) [19]. Для питча: «рынок только начинает, у ПОЛИПЛАСТИК шанс стать витринным кейсом».

## 8. Подводные камни Telegram → MAX и обходы

| Нет или иначе в MAX | Обход |
|---|---|
| Reply-клавиатура (замена клавиатуры) не документирована [11] | Inline-кнопки типа `message` дают тот же эффект: текст от пользователя [5] |
| Нативных опросов (poll) нет [11] | Callback-шкалы 1–10 и свои анкеты. Для длинных анкет форма в Mini App |
| Inline-режим, платежи, `login_url`, `switch_inline_query` [11] | Не нужны «Корсику» |
| Создания чата ботом нет, добавление участников ограничено с 09.09.2026 [1][3] | Бот-ретранслятор (раздел 4) |
| Отложенной отправки нет [5] | Свой scheduler + очередь |
| Long polling не для прода, webhook только 443 и доверенный УЦ [4][5] | Caddy + Let's Encrypt на поддомене, сервис за ним |
| Создание бота только для верифицированной организации, модерация до 48 рабочих часов [10] | Завести бота **сегодня**. Параллельно мок-сервер API по OpenAPI-схеме для разработки и демо |
| Текст до 4000 символов против 4096 в TG [2] | Резать ответы RAG по 3500 символов |
| Правка и удаление только для сообщений младше 24 ч [11] | Не править старые карточки, слать новые |
| Медиа после загрузки бывает «не готово» → 400 [5] | Ретрай с backoff, кэш токенов |
| `GET /chats` не поддерживается с июня 2026 [1] | Хранить `chat_id` из событий `bot_added` и `bot_started` у себя |
| Форматирование только в новых клиентах (iOS 3.1+, Android 2.20+) [5] | Тексты должны читаться и без разметки |
| Поле `notify=false` в канале даёт ошибку [5] | Тихие сообщения только в личке и группах |

## Рекомендованная архитектура интеграционного слоя

```
 QR на оффере ──► max.ru/<bot>?start=<onboarding_token>
                                   │ bot_started.payload
                                   ▼
 MAX platform-api2.max.ru ──HTTPS:443 webhook (X-Max-Bot-Api-Secret)──► [Caddy] ─► FastAPI
       ▲                                                                       │
       │ POST /messages, /answers, /uploads (≤25 rps, ≤2 msg/s/диалог)        ▼
       │                                                         maxapi Dispatcher/Routers
 ┌─────┴──────────────┐                                         ├─ onboarding router (FSM в Redis)
 │ MaxGateway         │◄── outbox queue (Redis/Celery) ◄────────├─ pulse-survey router (callback 1–10)
 │ - token bucket     │                                         ├─ QA router → RAG (pgvector) + guardrails
 │ - retry 429/400    │                                         │      (цитаты из источников, порог уверенности,
 │ - upload cache     │                                         │       «не знаю → HR»)
 │   (PDF/image token)│                                         └─ escalation router ─► Ticket service
 └────────────────────┘                                                    │
       ▲                                                                   ├─► HR-группа в MAX (бот-админ):
       │                                                                   │   карточка тикета + forward,
 Scheduler (APScheduler/Celery beat)                                       │   reply рекрутера → новичку
  └─ touchpoints(employee, step, due_at, status)                           └─► Mini App «HR-дашборд»
     T-3д, Д1 09:00/12:00/17:00, Д3, 2н, 1м, 2м, конец ИС                       (open_app, initData HMAC)
     + напоминания по неотвеченным опросам
                                                        Sentiment-классификатор ответов ─► red flag
 Postgres: employees(site=GrPP|GTP|Luzhniki, max_user_id, chat_id, start_date),     → тикет + алерт HR
           surveys, answers, sentiment, tickets, messages_log
```

Принципы:
1. Всё общение с MAX идёт через один `MaxGateway`: лимиты, ретраи, кэш загрузок, подмена на мок в тестах.
2. Бизнес-логика (таймлайн, опросы, RAG, sentiment) от MAX не зависит, поэтому её можно переиспользовать для Telegram или веба.
3. Состояние «тикет открыт» глушит AI-ответы в этом диалоге, чтобы бот не перебивал рекрутера.
4. Webhook идемпотентен по `timestamp` + `callback_id`/`mid`, потому что MAX ретраит доставку до 8 ч.
