# План разработки «Корсик 2.0»

Технический план реализации того, что описано в [plan.md](plan.md): стек, архитектура, модули, данные, дизайн, порядок сборки. Всё разрабатываем и запускаем в Docker Compose.

---

## 1. Стек

| Слой | Что используем |
|---|---|
| Язык и бэкенд | Python 3.12, FastAPI, asyncio, Pydantic v2, SQLAlchemy 2 (async) + Alembic |
| Бот «МАКС» | `maxapi` (Python-SDK в стиле aiogram), long polling; состояние диалога — в Postgres |
| Планировщик | APScheduler (AsyncIOScheduler), тик раз в минуту; производственный календарь РФ на 2026 год (JSON) |
| База данных | PostgreSQL 16 + pgvector (HNSW, cosine) + полнотекстовый поиск (`russian`, GIN) |
| Эмбеддинги | `BAAI/bge-m3` на CPU (sentence-transformers, CPU-сборка torch), размерность 1024 |
| LLM | GigaChat API (Python-SDK `gigachat`, сертификат НУЦ Минцифры в образе) |
| Разбор документов | Docling (PDF и PPTX → структура с номерами страниц и слайдов) |
| Импорт сценария | openpyxl |
| Mini App | React + Vite + TypeScript, UI-кит MAX UI, MAX Bridge (`window.WebApp`), `motion` (анимации), Lucide (иконки) |
| Картинка отчёта | HTML-шаблон (Jinja2) → PNG через Playwright (Chromium + шрифты с кириллицей) |
| Запуск | Docker Compose (локально — Docker Desktop, arm64; сервер — VPS), Caddy (HTTPS) |
| Качество | pytest, ruff, скрипт оценки на эталоне |

## 2. Архитектура

```
 Новичок / Руководитель / Глава подбора / HR-группа            HR и руководитель
              │  чат с ботом «Корсик» в «МАКС»                  │  Mini App (WebView «МАКС»)
              ▼                                                  ▼
 ┌──── «МАКС» Bot API (platform-api2.max.ru) ────┐        ┌──── Caddy (HTTPS) ────┐
 └──────────────▲────────────────────────────────┘        └──────────▲────────────┘
                │ long polling, POST /messages, /answers, /uploads    │ REST + initData
 ┌──────────────┴─────────────────────────────────────────────────────┴───────────┐
 │  app (Python, один процесс)                                                     │
 │   bot/      — события, меню, кнопки, очередь отправки                           │
 │   scenario/ — сценарий из xlsx, планировщик, рабочий календарь, машина времени  │
 │   surveys/  — движок опросов                                                    │
 │   kb/       — база знаний, поиск, ответы                                        │
 │   signals/  — флаги и разбор ответов опросов                                    │
 │   tickets/  — обращения к HR                                                    │
 │   reports/  — еженедельная сводка, картинка                                     │
 │   api/      — REST для Mini App                                                 │
 │   privacy/  — маскирование, журнал обращений к LLM                              │
 │   тяжёлые задачи (эмбеддинги, Docling, рендер PNG) — в пуле run_in_executor     │
 └───────┬───────────────────────────┬──────────────────────────────┬─────────────┘
         ▼                           ▼                              ▼
   PostgreSQL + pgvector       GigaChat API (облако РФ)       bge-m3 (локально, CPU)
```

Один бэкенд-процесс (бот, планировщик, API) + Postgres + Mini App за Caddy. К Bot API ходит только бот; Mini App обращается к нашему API.

## 4. Модули

### 4.1. Бот и интеграция с «МАКС» (`bot/`)
- Long polling через `maxapi` запускается задачей в `lifespan` FastAPI; при старте снимается webhook-подписка (`DELETE /subscriptions`).
- Обработчики: `bot_started`, `message_created`, `message_callback`, `bot_stopped`, `bot_added` (HR-группа).
- **Привязка:** ссылка `max.ru/<бот>?start=<код>` (код случайный, `[A-Za-z0-9_-]`, без персональных данных) → `bot_started.payload` → привязка `max_user_id` и `chat_id` к карточке новичка или сотрудника (HR, руководитель, глава подбора). Запасной вход — ввод кода текстом. Формат ссылки проверяем на тестовом боте в первый день.
- **Первое сообщение:** согласие на сопровождение и отдельно — на ИИ-анализ ответов; выбор «ты/вы».
- **Меню команд** через `PATCH /me`: `/start`, `/hr`, `/food`. Inline-кнопки — `callback`, `link`, `open_app`.
- **Маршрут свободного текста** по `dialog_state`: ждём ответ опроса → `surveys/`; ждём текст для обращения → `tickets/`; ответ в течение 30 минут после сообщения HR → в этот тикет; иначе → вопрос в `kb/`.
- Каждый `message_callback` закрывается `POST /answers` (сообщение заменяется отметкой выбора).
- **Очередь отправки:** не больше 2 сообщений/с в диалог и 30 запросов/с на бота; 429 → повтор с паузой; 403 `chat.denied` → статус «остановил бота» без повторов; текст длиннее 3500 символов делится на части.
- **Вложения:** файл из `assets/` загружается через `POST /uploads` один раз, токен кэшируется; «файл ещё не готов» → повтор с паузой.
- Все сообщения пишутся в `messages`. `bot_stopped` → статус в карточке и уведомление HR.

### 4.2. Сценарий и планировщик (`scenario/`)
- **Импорт xlsx:** 68 шагов → `scenario_steps`. Время разбирается правилами («За 2-3 дня до выхода», «В первый рабочий день в 10:00», «Во второй рабочий день», «Через 1 месяц и 2 недели», «Первый день второго месяца», «Последний день ИС»); редкие случаи — в YAML-файле поправок.
- **Новые площадки:** новые теги из xlsx показываются HR списком; HR задаёт название и часовой пояс → запись в `sites`. Повторный импорт заменяет шаги; уже отправленное не дублируется (ключ идемпотентности).
- **Персонализация:** шаги по тегу площадки и признаку «для офисных»; подстановка имени вместо «Х» и «Имя кандидата». Выбор «ты/вы» применяется к собственным фразам бота (шаблоны в двух вариантах); тексты сценария — как в ТЗ.
- **Рабочие дни:** «N-й рабочий день» считается по производственному календарю РФ; шаг, выпавший на выходной, переносится на следующий рабочий день на то же время.
- **Тик раз в минуту:** для каждого активного новичка определяет наступившие шаги (часовой пояс площадки + смещение часов) и кладёт их в `deliveries`. Неактуальный шаг (дата прошла) не отправляется.
- **Ветки:** у кнопки шага есть `next_step` — например, «Подсказать, где пообедать? — Да» → файл площадки; `/food` присылает тот же файл.
- **Вложения:** колонка «Сопроводительное изображение» сопоставляется с файлом в `assets/` (например, `img_04.png`, `food_GTP.pdf`, `map_GTP.pdf`); нет файла — заглушка с подписью «макет».
- **Шаги по отмашке рекрутера:** «представлю тебя коллегам» — бот ждёт текст и фото и показывает их рекрутеру в карточке новичка; «адаптационный план» — HR или руководитель нажимает «План готов» в Mini App и прикладывает файл, бот отправляет шаг с файлом.
- **Конец испытательного** — из срока в карточке.
- **Напоминание** о непройденном опросе — новым сообщением на следующий день и через день.
- **Машина времени:** у тестового пользователя смещение часов; в Mini App HR перемотка на ключевые дни (−2, 1, 3, 14, 60, конец испытательного), опросы ждут ответа.

### 4.3. Опросы (`surveys/`)
- Все опросы из ТЗ: 3-й день, чек 2-й недели, адаптационный план, 2 месяца, финальный.
- Типы вопросов: варианты, да/нет, шкала 1–10 (две строки по 5 кнопок), мультивыбор, «свой вариант», открытый.
- Оценка ниже 8 или ответ «нет» → «что мешает?» (свободный текст).
- «Связаться с рекрутером» → тикет закреплённому рекрутеру с пометкой «просит связаться»; «Передать проблему в подбор» → новичок пишет текст → тикет.
- Кнопки-триггеры (в YAML): «Нет, задумываюсь об уходе» → флаг «намерение уйти»; «Уже устал, а задачи все валятся», «Никто!», «Пока ничего не понял», «Я отстаю от графика» → жёлтый флаг с темой.
- На вопрос о доступах в первый день при ответе «Нет» у новичка появляется кнопка «Напомнить руководителю про доступы» — push руководителю уходит только по ней.
- Каждый свободный ответ уходит в `signals/`.

### 4.4. База знаний и ответы (`kb/`)
- **Стартовое наполнение:** `docs/pvtr.md`, `docs/anticorruption-policy.md`, `docs/trade-secret.md` (с пометкой КТ), `docs/quality-ecology-policy.md` и справочные тексты шагов сценария (документы для оформления, справочник, обед, транспорт, доступы) + черновик статьи «Доступ к корпоративному порталу» (статус «черновик HR»).
- **Нарезка:** ПВТР — по пунктам `6.x.y` с путём «раздел → пункт» и страницей из маркеров `<!-- стр. N -->`; презентации — слайд = фрагмент; шаги сценария — статья с тегами площадок.
- **Индексация** (в пуле `run_in_executor`): `bge-m3` → `embedding`; текст → `tsvector`. Индексы: GIN по `tsvector`, HNSW (cosine) по `embedding`; миграция включает `CREATE EXTENSION vector`.
- **Поиск:** запрос расширяется синонимами в Python («зарплата» ↔ «заработная плата», «больничный» ↔ «нетрудоспособность»); полнотекстовый — `to_tsquery('russian', …)` с OR по леммам и `ts_rank_cd`; векторный — cosine; объединение по рангам (RRF); фильтр по площадке новичка.
- **Маршрут вопроса:**
  1. Правила личных кадровых случаев (первое лицо + «не пришла зарплата», «увольняют», «заболел» и т. п.) → тикет HR, без LLM. При сомнении — к HR.
  2. Поиск. Лучший результат выше высокого порога → ответ сразу.
  3. Между порогами → GigaChat выбирает лучший пункт из топ-5 (JSON с `chunk_id` или «нет подходящего»); код проверяет, что `chunk_id` из найденных. Фрагменты с пометкой КТ в LLM не отправляются.
  4. Ниже нижнего порога или «нет подходящего» → «не знаю, передал HR, ответ придёт сюда» → тикет.
- **Карточка ответа:** подводка по шаблону в тоне Корсика («ты/вы») + дословный пункт + источник («ПВТР, п. 6.5.2, стр. 15»; для черновика — «Черновик HR, ждёт подтверждения») + кнопка «Связаться с HR».
- **Ответы HR в базу:** HR отвечает на тикет в Mini App и отмечает «в базу» с тегом площадки → `hr_answers` + индексация; источник — «ответ HR от <дата>». У личных вопросов и флагов отметки «в базу» нет.
- **Загрузка документов HR:** PDF или PPTX через Mini App или файлом боту в личку → Docling (`DoclingDocument` + `HybridChunker`, страница и слайд из `prov.page_no`, OCR выключен для текстовых PDF) → нарезка → индексация. Новая версия заменяет старую, пометка КТ ставится при загрузке.
- Пороги поиска подбираются на эталоне (раздел 4.11).

### 4.5. Сигналы из опросов (`signals/`)
- **Правила (всегда, локально):** словарь лемм красных флагов — безопасность и охрана труда, травля и унижения, угрозы, здоровье. Срабатывание → красный флаг + тикет HR сразу + уведомление в HR-группу; новичку — «передал HR, увидит только HR».
- **Кнопки-триггеры** опросов дают флаги (раздел 4.3).
- **LLM (при согласии на ИИ-анализ):** GigaChat разбирает свободный ответ → JSON: тема из фиксированного списка (доступы, документы, наставник, руководитель, коллектив, понимание задач, нагрузка, быт и транспорт, обучение, охрана труда, другое), настроение (негатив / нейтрально / позитив), дословная цитата-доказательство. Код проверяет, что цитата есть в тексте ответа. JSON — через function calling или строгий разбор с повтором.
- Нетревожные темы → агрегаты для HR и сводки; личная передача HR — по кнопке «Передать HR?».

### 4.6. Обращения к HR (`tickets/`)
- Источники: кнопка «Связаться с HR», `/hr`, «не знаю», личный кадровый вопрос, флаг, кнопки опросов.
- Обращение уходит закреплённому рекрутеру новичка. Карточка: ФИО, площадка, день адаптации, категория, дословная цитата, последние сообщения из `messages`.
- **HR-группа «МАКС»:** бот — участник-админ; `chat_id` группы записывается при добавлении бота. Бот публикует уведомление о новом обращении или флаге с кнопкой «Открыть в Mini App».
- HR отвечает из Mini App → бот отправляет ответ новичку в его чат с подписью «Имя (HR)». Ответы новичка в течение 30 минут после этого попадают в тот же тикет.
- Статусы: новый → в работе → закрыт.

### 4.7. Mini App (`miniapp/`)
- `index.html` подключает скрипт MAX Bridge; фронт отправляет `initData` в заголовке каждого запроса; бэкенд проверяет HMAC-SHA256 (ключ от токена бота) и что `auth_date` не старше 24 часов; роль — по `user.id` → `staff.max_user_id`.
- **HR:**
  - «Новички»: список (площадка, день N из срока, текущий шаг, непройденные опросы, открытые обращения), карточка новичка (включая текст и фото «представления коллегам»);
  - «Завести новичка»: форма (ФИО, площадка, офис/производство, дата выхода, срок испытательного, руководитель, рекрутер) → ссылка и QR для оффера; охват — кто ещё не подключился;
  - «Обращения»: очередь тикетов и флагов, ответ в чат новичку, отметка «в базу», кнопка «План готов» с файлом;
  - «База знаний»: загрузка PDF/PPTX, загрузка xlsx сценария (с подтверждением новых площадок), список документов (статус, пометка КТ) и ответов HR;
  - «Частые темы»: топ тем вопросов по дням адаптации;
  - «Демо»: перемотка времени тестового новичка, кнопка «Сформировать сводку».
- **Руководитель:** «Мои новички» (день N, ближайшая встреча), отметка «Провёл», кнопка «План готов».

### 4.8. Руководитель (`scenario/` + `tickets/`)
- Push в чат руководителю «проведи встречу с <новичок>» на 3-й, 30-й, 60-й день и за 5 дней до конца испытательного — кнопки «Провёл» и «Открыть в Mini App».
- Push «напомнить про доступы» — только по кнопке новичка (раздел 4.3).
- Ответы опросов и обращения своих новичков руководитель не получает.

### 4.9. Еженедельная сводка (`reports/`)
- Раз в неделю и по кнопке в Mini App — агрегаты за 4 недели по площадкам: новички, средние оценки, настроение, топ-3 темы, закрытые и открытые сигналы.
- Срез по площадке выводится, если ответили 5 и больше **разных новичков**; иначе площадки объединяются с пометкой «мало данных». Имён и цитат нет.
- HTML-шаблон → PNG (Playwright, браузер запускается один раз и переиспользуется) → сообщение-картинка главе подбора в «МАКС».

### 4.10. Защита данных (`privacy/`)
- Перед каждым вызовом GigaChat: замена ФИО из карточек и `regex` телефонов и e-mail на метки.
- Тексты с темой «здоровье» и фрагменты с пометкой КТ в LLM не отправляются.
- `llm_log`: время, тип вызова, классы данных — без самих текстов.
- ИИ-разбор ответов — только при согласии `ai_analysis`.

### 4.11. Оценка качества (`eval/`)
- Эталон: 73 вопроса Ивана (`eval/golden.jsonl` из ветки `ideas/ivan`: 50 отвечаемых, 15 эскалаций, 8 вне базы) + вопросы от людей вне команды.
- Скрипт прогоняет вопросы через `kb/` → таблица: верный источник, лишние отказы, перехват личных вопросов, доля ответов без HR.
- Флаги: 120 синтетических ответов (`eval/survey-synth.jsonl`) + 10 дописанных примеров «угрозы» и «здоровье»; метки сопоставляются (`safety_issue` → безопасность, `toxicity` → травля, `intent_to_leave` → намерение уйти, остальные → темы) → точность и полнота по каждому флагу.
- Результат — таблица в README и цифры на слайд.

### 4.12. Демо-данные (`seed/`)
- Площадки GTP, Luzhniki, GrPP; сотрудники HR, рекрутер, руководитель, глава подбора.
- Коды привязки для аккаунтов команды: новичок GTP, новичок Luzhniki, HR, руководитель, глава подбора.
- По 6–8 синтетических новичков на площадку без аккаунта «МАКС»; 120 синтетических ответов распределяются между ними по площадке, даты — за последние 6 недель, чтобы сводка и порог «5 человек» работали.
- Все данные помечены как синтетические.

## 5. Дизайн

Ориентир — подход Apple, перенесённый в веб (скиллы `apple-design`, `mobile-native`, `emil-design-eng`, `ui-ux-pro-max`): интерфейс отвечает мгновенно, ведёт себя физически, ничего лишнего. Настроение — спокойный корпоративный, вызывающий доверие; тепло даёт тон Корсика в текстах, а не украшения.

### 5.1. Принципы
- **Простота, а не минимализм.** На каждом экране одно главное действие, второстепенное — на уровень глубже.
- **Привычность.** Паттерны iOS / «МАКС»: сгруппированные списки, нижние вкладки, листы снизу, «назад» слева сверху.
- **Мгновенный отклик.** Нажатие подсвечивается на касании (`:active`, `scale(0.97)`, 100 мс), загрузка дольше 300 мс — скелетон.
- **Wayfinding.** Каждый экран отвечает: где я, что здесь, куда дальше, как выйти.
- **Обратная связь четырёх видов:** статус, успех, предупреждение, ошибка — с иконкой и текстом, не только цветом.

### 5.2. Токены
| Токен | Светлая | Тёмная |
|---|---|---|
| `--bg` (фон экрана) | `#F2F2F7` | `#000000` |
| `--surface` (карточки, ячейки) | `#FFFFFF` | `#1C1C1E` |
| `--text` | `#111827` | `#F5F5F7` |
| `--text-secondary` | `#6B7280` | `#A1A1AA` |
| `--primary` (действия, ссылки) | `#2563EB` | `#3B82F6` |
| `--success` | `#16A34A` | `#22C55E` |
| `--warning` | `#D97706` | `#F59E0B` |
| `--danger` (красные флаги) | `#DC2626` | `#F87171` |
| `--separator` | `#E5E7EB` | `#2C2C2E` |

- Тема — по `prefers-color-scheme`. Контраст текста ≥ 4,5:1 в обеих темах.
- Отступы — шкала 4 / 8 / 12 / 16 / 24 / 32; радиусы — 10 (ячейки), 14 (карточки), 999 (чипы).
- Иконки — Lucide (SVG, одна толщина линии 1,75), без эмодзи в интерфейсе Mini App.

### 5.3. Типографика
- Системный шрифт (`system-ui`: SF на iOS, Roboto на Android) — кириллица и оптические размеры из коробки.
- Шкала: 13 (подписи) / 15 (вторичный) / 17 (основной) / 20 (заголовок раздела) / 28 (заголовок экрана).
- Трекинг по размеру: заголовки −0,02em, основной текст 0. Межстрочный: заголовки 1,15, текст 1,45.
- Иерархия — вес + размер: заголовки 600–700, текст 400, подписи 500. Цифры в таблицах — `tabular-nums`.
- Поля ввода — 16 px (без автозума на iOS); размеры в `rem`, чтобы уважать системный размер шрифта.

### 5.4. Экраны Mini App
**HR — нижняя панель из 4 вкладок** (иконка + подпись): «Новички», «Обращения» (бейдж с числом открытых), «База», «Ещё».

- **Новички:** поиск сверху; сгруппированный список по площадкам; ячейка — ФИО, «день N из M» с тонкой полосой прогресса, чипы-статусы (непройденный опрос, открытое обращение). Кнопка «+ Новичок» в шапке.
- **Карточка новичка:** шапка (ФИО, площадка, офис/производство, полоса прогресса испытательного) → секции «Ближайшие шаги», «Опросы», «Обращения», «Контакты (руководитель, рекрутер)».
- **Завести новичка:** сгруппированная форма с подписями над полями, `type="date"` для даты выхода, сегмент «Офис / Производство», выбор площадки и руководителя. После сохранения — лист снизу с QR, кнопками «Скопировать ссылку» и «Поделиться».
- **Обращения:** сегмент «Открытые / В работе / Закрытые»; карточка — категория (красный флаг — иконка и красная метка), площадка, день, первая строка цитаты, таймер срока. Экран обращения — лента сообщений как в чате, внизу закреплённое поле ответа (с учётом `safe-area`), над ним «Взять» / «Закрыть» и переключатель «Добавить ответ в базу» + выбор площадки.
- **База:** список документов (иконка типа, метка «КТ», дата версии), кнопка «Загрузить» → прогресс → итог «Готово: 42 фрагмента»; вкладка «Ответы HR»; загрузка xlsx сценария с отчётом по строкам.
- **Ещё:** «Частые темы» (горизонтальные столбцы с числами + таблица), «Демо» (сегмент перемотки −2 / 1 / 3 / 14 / 60 / конец, кнопка «Сформировать сводку»).

**Руководитель — один экран без вкладок:** «Мои новички» (ячейка: ФИО, день N, ближайшая встреча) → карточка с кнопкой «Провёл встречу». Пустое состояние — объяснение и что будет дальше.

### 5.5. Сообщения бота
- **Карточка ответа:** строка-подводка в тоне Корсика → цитата блоком (`> …`) → строка «Источник: ПВТР, п. 6.5.2, стр. 15» → кнопка «Связаться с HR» (кнопка «Открыть документ» добавляется с бонусом из раздела 9).
- **«Не знаю»:** честная фраза + что будет дальше («передал HR, ответ придёт сюда») + кнопка «Задать другой вопрос».
- **Опросы:** один вопрос — одно сообщение; варианты кнопками в столбик, шкала 1–10 — две строки по 5; после ответа сообщение заменяется итогом (`POST /answers`), чтобы чат не захламлялся.
- **Красный флаг:** серьёзный тон без эмодзи, короткий текст «передал HR, увидит только HR» + телефоны ночью.
- Форматирование — markdown «МАКС», подписи кнопок короткие (до 30 знаков, лимит API 128).

### 5.6. Движение
- Библиотека — `motion` (Framer Motion) для React: пружины прерываемы и стартуют с текущего значения.
- Переходы между экранами — горизонтальный сдвиг «вперёд вправо / назад влево», пружина без отскока (`bounce 0`, `duration 0.35`).
- Листы снизу — тянутся пальцем 1:1, отпускание с учётом скорости (проекция импульса), лёгкий отскок (`bounce 0.15`); закрываются туда же, откуда пришли.
- Появление списков — короткий каскад 30 мс на элемент, только при первом показе.
- `prefers-reduced-motion` — вместо сдвигов и пружин короткое затухание 200 мс; `prefers-reduced-transparency` — плотные фоны вместо размытия.
- Шапка и нижняя панель — полупрозрачный материал (`backdrop-filter: blur(20px) saturate(180%)`), контент прокручивается под ними.

### 5.7. Мобильная база
- `viewport`: `width=device-width, initial-scale=1, viewport-fit=cover, interactive-widget=resizes-content` (без запрета зума).
- Высота приложения — `100dvh`; отступы `env(safe-area-inset-*)` для шапки, нижней панели и поля ввода.
- `-webkit-tap-highlight-color: transparent`, `touch-action: manipulation` на кнопках, `:hover` только внутри `@media (hover: hover) and (pointer: fine)`.
- Цели касания ≥ 44 × 44, расстояние между ними ≥ 8.
- Проверка на реальном телефоне внутри «МАКС» (iOS и Android), а не только в эмуляторе.

### 5.8. Картинка еженедельной сводки
Формат 1080 × 1350: заголовок с датами недели → три KPI-карточки (новички, средняя оценка, открытые сигналы) → столбцы настроения по площадкам → топ-3 темы с числом упоминаний → строка «мало данных» для мелких площадок. Те же токены и шрифт, светлая тема.

## 7. Запуск и деплой

**Локально — Docker Compose** (Docker Desktop, Apple Silicon / arm64):
- `docker compose up` поднимает `postgres` (pgvector), `app` (бот + планировщик + API, код смонтирован томом, автоперезапуск) и `miniapp` (Vite dev-server с hot-reload);
- миграции, демо-данные, импорт сценария и оценка — `make migrate`, `make seed`, `make import`, `make eval` (внутри `docker compose exec app …`);
- веса `bge-m3` и моделей Docling скачиваются один раз в именованный том;
- тестовый бот опрашивает только один запущенный экземпляр — у того, кто сейчас разрабатывает бота, или на сервере.

**Сервер:**
- VPS: 4 vCPU, 8+ ГБ ОЗУ; Docker Compose: `postgres`, `app`, `caddy` (собранная статика Mini App).
- Поддомен с A-записью на VPS; Caddy выдаёт HTTPS; этот URL зарегистрирован как Mini App в настройках тестового бота на business.max.ru.
- В образе `app`: CPU-сборка torch, сертификат НУЦ Минцифры, `playwright install --with-deps chromium`, шрифты с кириллицей (`fonts-noto-core`).
- Секреты — в `.env` на сервере, в репозитории только `.env.example`.

## 8. Порядок сборки

1. **Каркас:** публичный репозиторий с README (ссылка в ЛК после чек-поинта 1), Docker Compose, Postgres + миграции, бот отвечает на `/start` с кодом и привязывает пользователя, согласие и «ты/вы».
2. **Сценарий:** импорт xlsx, календарь, планировщик, отправка шагов с кнопками, ветками и вложениями, машина времени. Проверка на двух площадках.
3. **Ответы:** нарезка и индексация документов, поиск, маршрут вопроса, карточка ответа, «не знаю → HR».
4. **Обращения и Mini App HR:** тикеты, ответ HR в чат новичку, уведомления в HR-группу, экраны «Новички» и «Обращения», вход по `initData`, ответы HR в базу.
5. **Опросы и сигналы:** движок опросов, «что мешает?», напоминания, кнопки-триггеры, правила флагов, разбор LLM.
6. **Руководитель и сводка:** push «проведи встречу», экран руководителя, еженедельная сводка картинкой.
7. **Загрузка документов и xlsx** из Mini App и файлом боту.
8. **Качество и демо:** скрипт оценки, демо-данные, прогон сценария демо, запись видео-страховки.
9. **Бонусы** (раздел 9).

## 9. Бонусы (после основы)

| Бонус | Как сделать |
|---|---|
| «Открыть документ» с подсветкой пункта | Кнопка в карточке ответа → экран Mini App: текст документа из `kb_chunks`, прокрутка и подсветка цитируемого пункта по `chunk_id` |
| «Ты спрашивал про … — вот ответ» | При публикации ответа HR в базу найти в `questions_log` похожие неотвеченные вопросы и разослать ответ их авторам |
| Аудит сценария | Проверки при импорте xlsx: промежутки без опросов, шаги без действия, руководитель без касаний → отчёт в Mini App |
| «Вторая площадка за 5 минут» | Загрузка xlsx с новым тегом площадки → подтверждение площадки → тестовый новичок с её кодом получает её шаги |
| Пульс «совпало ли с обещанным?» | Две новые строки сценария: 7-й день и 5-я неделя |
| Кривая настроения и флаг падения оценок | Линия «неделя × площадка» в сводке; правило: падение на ≥ 3 пункта → жёлтый флаг |
| Подсказки «Спроси меня про…» | Кнопки-темы под приветствием и после «не знаю» из отвечаемых вопросов эталона |
