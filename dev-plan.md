# План разработки «Корсик 2.0»

Технический план реализации того, что описано в [plan.md](plan.md): стек, архитектура, модули, данные, порядок сборки.

---

## 1. Стек

| Слой | Что используем |
|---|---|
| Язык и бэкенд | Python 3.12, FastAPI, asyncio, Pydantic v2, SQLAlchemy 2 (async) + Alembic |
| Бот «МАКС» | `maxapi` (Python-SDK в стиле aiogram: роутеры, фильтры, FSM), long polling |
| Планировщик | APScheduler (AsyncIOScheduler), тик раз в минуту |
| База данных | PostgreSQL 16 + pgvector (векторный поиск) + встроенный полнотекстовый поиск (`russian`) |
| Эмбеддинги | `BAAI/bge-m3` на CPU (sentence-transformers) |
| LLM | GigaChat API (официальный Python-SDK `gigachat`) |
| Разбор документов | Docling (PDF и PPTX → Markdown со структурой) |
| Импорт сценария | openpyxl |
| Mini App | React + Vite + TypeScript, UI-кит MAX UI, MAX Bridge (`window.WebApp`), `motion` (анимации), Lucide (иконки) |
| Картинка отчёта | HTML-шаблон (Jinja2) → PNG через Playwright (headless Chromium) |
| Деплой | Docker Compose на VPS, Caddy (HTTPS, раздача Mini App) |
| Качество | pytest, ruff, скрипт оценки на эталоне |

## 2. Архитектура

```
 Новичок / Руководитель / Глава подбора           HR (Mini App / группа HR в «МАКС»)
              │  чат с ботом «Корсик»                          │
              ▼                                                 ▼
 ┌──────────────── «МАКС» Bot API (platform-api2.max.ru) ────────────────┐
 └───────────────▲──────────────────────────────────────────▲─────────────┘
                 │ long polling / POST /messages              │ Mini App (HTTPS, initData)
 ┌───────────────┴──────────────────────────────────────────┴─────────────┐
 │  app (Python, один процесс)                                             │
 │   bot/        — приём событий, меню, кнопки, отправка через очередь     │
 │   scenario/   — сценарий из xlsx, планировщик, машина времени           │
 │   surveys/    — движок опросов                                          │
 │   kb/         — база знаний, поиск, ответы                              │
 │   signals/    — анализ ответов опросов, красные флаги                   │
 │   tickets/    — обращения к HR, ретрансляция ответов                    │
 │   reports/    — еженедельная сводка, картинка                           │
 │   api/        — REST для Mini App                                       │
 │   privacy/    — маскирование, журнал обращений к LLM                    │
 └───────┬─────────────────────────┬───────────────────────────┬──────────┘
         ▼                         ▼                           ▼
   PostgreSQL + pgvector     GigaChat API (облако РФ)     bge-m3 (локально, CPU)
```

Один бэкенд-процесс (бот, планировщик, API) + Postgres + статика Mini App за Caddy.

## 4. Модули

### 4.1. Бот и интеграция с «МАКС» (`bot/`)
- Long polling через `maxapi`; обработчики событий `bot_started`, `message_created`, `message_callback`, `bot_stopped`.
- `bot_started` с кодом из ссылки `max.ru/<бот>?start=<код>` → привязка `max_user_id` к карточке новичка или сотрудника (руководитель, HR); запасной вход — ввод кода из письма.
- Первое сообщение: согласие на сопровождение и отдельно — на ИИ-анализ ответов; выбор «ты/вы».
- Меню команд: `/start`, `/HR`, `/Food`, «Мой путь»; inline-кнопки сценария и ответов (`callback`, `link`, `open_app`).
- Свободный текст: если ждём ответ на опрос — в `surveys`, иначе — в `kb` (вопрос) или в открытый тикет.
- Очередь отправки: не больше 2 сообщений/с в диалог и 30 запросов/с на бота, повтор при 429.
- Вложения: загрузка через `POST /uploads`, кэш токенов файлов.
- `bot_stopped` → отметка в карточке и сигнал HR.

### 4.2. Сценарий и планировщик (`scenario/`)
- Импорт xlsx: 68 шагов → `scenario_steps`. Время шага разбирается правилами («За 2-3 дня до выхода», «В первый рабочий день в 10:00», «Через 1 месяц и 2 недели», «Последний день ИС»), редкие случаи — в YAML-файле поправок.
- Персонализация: теги площадок, признак «для офисных», обращение «ты/вы».
- Тик раз в минуту: для каждого активного новичка считает, какие шаги наступили (с учётом часового пояса площадки и смещения часов), и кладёт их в `deliveries` с ключом идемпотентности. Шаг, который уже неактуален, не отправляется.
- Напоминание о непройденном опросе: на следующий день и через день.
- Шаги «по отмашке рекрутера» запускаются событием: HR или руководитель нажал «план готов» / «представить коллегам» в Mini App.
- Конец испытательного считается из срока в карточке; паузы (больничный и т. п.) HR ставит в Mini App.
- Машина времени: у тестового пользователя смещение часов; в Mini App HR кнопки перемотки на ключевые дни (−2, 1, 3, 14, 60, конец испытательного).

### 4.3. Опросы (`surveys/`)
- Все опросы из ТЗ: 3-й день, чек 2-й недели, адаптационный план, 2 месяца, финальный.
- Типы вопросов: варианты, да/нет, шкала 1–10, мультивыбор, «свой вариант», открытый.
- Оценка ниже 8 или ответ «нет» → «что мешает?» (свободный текст).
- Ветки ТЗ: кнопки «Связаться с рекрутером» и «Передать проблему в подбор» → тикет.
- Каждый свободный ответ уходит в `signals/`.

### 4.4. База знаний и ответы (`kb/`)
- **Стартовое наполнение:** `docs/pvtr.md`, `docs/anticorruption-policy.md`, `docs/trade-secret.md`, `docs/quality-ecology-policy.md` и справочные тексты шагов сценария (документы для оформления, справочник, обед, транспорт, доступы).
- **Нарезка:** ПВТР — по пунктам `6.x.y` с путём «раздел → пункт» и страницей из маркеров `<!-- стр. N -->`; презентации — слайд = фрагмент; шаги сценария — статья с тегами площадок.
- **Индексация:** `bge-m3` → `embedding` в pgvector; текст → `tsvector` для полнотекстового поиска.
- **Поиск:** полнотекстовый + векторный, объединение по рангам (RRF), фильтр по площадке новичка, синонимы частых слов («зарплата» ↔ «заработная плата», «больничный» ↔ «нетрудоспособность»).
- **Маршрут вопроса:**
  1. Правила личных кадровых случаев (первое лицо + «не пришла зарплата», «увольняют», «заболел» и т. п.) → тикет HR, без LLM.
  2. Поиск. Лучший результат выше высокого порога → ответ сразу.
  3. Между порогами → GigaChat выбирает лучший пункт из топ-5 (ответ — JSON с `chunk_id` или «нет подходящего»); код проверяет, что `chunk_id` из найденных. Фрагменты с пометкой КТ в LLM не отправляются.
  4. Ниже нижнего порога или «нет подходящего» → «не знаю, передал HR» → тикет.
- **Карточка ответа:** подводка по шаблону в тоне Корсика («ты/вы») + дословный пункт + источник («ПВТР, п. 6.5.2, стр. 15») + кнопки «Связаться с HR», «Открыть документ».
- **Ответы HR в базу:** HR в Mini App отвечает на тикет и отмечает «в базу» с тегом площадки → запись в `hr_answers` и индексация; источник в ответе — «ответ HR от <дата>».
- **Загрузка документов HR:** PDF или PPTX через Mini App → Docling → нарезка → индексация → документ доступен в поиске. Новая версия заменяет старую. Пометка КТ ставится при загрузке.
- Пороги поиска подбираются на эталоне (раздел 4.11).

### 4.5. Сигналы из опросов (`signals/`)
- **Правила (всегда, локально):** словарь лемм красных флагов — безопасность и охрана труда, травля и унижения, угрозы, здоровье, намерение уйти. Срабатывание → флаг + тикет HR сразу, новичку сообщение «передал HR, увидит только HR».
- **LLM (при согласии на ИИ-анализ):** GigaChat разбирает свободный ответ → JSON: тема из фиксированного списка (доступы, документы, наставник, руководитель, коллектив, понимание задач, нагрузка, быт и транспорт, обучение, охрана труда, другое), настроение (негатив / нейтрально / позитив), дословная цитата-доказательство. Код проверяет, что цитата есть в тексте ответа.
- Нетревожные темы → в агрегаты для HR и еженедельной сводки; личная передача HR — по кнопке «Передать HR?».

### 4.6. Обращения к HR (`tickets/`)
- Источники: кнопка «Связаться с HR», `/HR`, «не знаю», личный кадровый вопрос, красный флаг, кнопки опросов.
- Карточка: ФИО, площадка, день адаптации, категория, дословная цитата, последние сообщения.
- HR видит обращение в Mini App и в HR-группе «МАКС» (бот — админ группы, публикует карточку с кнопкой «Взять»).
- Ответ HR (из Mini App или reply в группе) бот пересылает новичку в его чат с подписью.
- Пока тикет открыт, бот не отвечает новичку сам — сообщения идут HR.
- Статусы: новый → в работе → закрыт; сроки: красные флаги — 15 минут, остальное — 2 рабочих часа; ночью по красной зоне новичку сразу уходят телефоны дежурного и 112.
- Обращения уходят закреплённому рекрутеру новичка.

### 4.7. Mini App (`miniapp/`)
- Вход из «МАКС»: проверка `initData` (HMAC-SHA256 с ключом от токена бота) на бэкенде, роль — по `staff`.
- **HR:**
  - «Новички»: список (площадка, день N из срока, текущий шаг, непройденные опросы, открытые обращения), карточка новичка;
  - «Завести новичка»: форма (ФИО, площадка, офис/производство, дата выхода, срок испытательного, руководитель, рекрутер) → ссылка и QR для оффера; охват — кто ещё не подключился;
  - «Обращения»: очередь тикетов и флагов, ответ в чат новичку, отметка «в базу»;
  - «База знаний»: загрузка PDF/PPTX, загрузка xlsx сценария, список документов и ответов HR;
  - «Частые темы»: топ тем вопросов по дням адаптации;
  - «Демо»: перемотка времени тестового новичка, кнопка «Сформировать сводку».
- **Руководитель:** «Мои новички» (день N, ближайшая встреча), отметка «Провёл».

### 4.8. Руководитель (`scenario/` + `tickets/`)
- Push в чат руководителю «проведи встречу с <новичок>» на 3-й, 30-й, 60-й день и за 5 дней до конца испытательного: кнопки «Провёл» и «Открыть в Mini App».
- Push «у новичка нет доступов», если новичок ответил «нет» на вопрос о доступах в первый день.
- Руководитель не получает ответов опросов и обращений своих новичков.

### 4.9. Еженедельная сводка (`reports/`)
- Раз в неделю (и по кнопке в Mini App) — агрегаты за 4 недели по площадкам: новички, средние оценки, настроение, топ-3 темы, закрытые и открытые сигналы.
- Срез по площадке выводится, если ответов 5 и больше; иначе площадки объединяются с пометкой «мало данных». Имён и цитат нет.
- HTML-шаблон → PNG (Playwright) → сообщение-картинка главе подбора в «МАКС».

### 4.10. Защита данных (`privacy/`)
- Перед каждым вызовом GigaChat: замена ФИО из карточек и `regex` телефонов и e-mail на метки.
- Тексты с темой «здоровье» и фрагменты с пометкой КТ в LLM не отправляются.
- `llm_log`: время, тип вызова, классы данных — без самих текстов.
- ИИ-разбор ответов — только при согласии `ai_analysis`.

### 4.11. Оценка качества (`eval/`)
- Эталон: 73 вопроса Ивана (`06-golden-set.jsonl`: 50 отвечаемых, 15 эскалаций, 8 вне базы) + вопросы от людей вне команды.
- Скрипт прогоняет вопросы через `kb/` → таблица: верный источник, лишние отказы, перехват личных вопросов, доля ответов без HR.
- Флаги: 120 синтетических ответов (`07-survey-answers-synth.jsonl`) → точность и полнота по каждому типу флага.
- Результат — таблица в README и цифры на слайд.

### 4.12. Демо-данные
- Скрипт заполнения: площадки GTP и Luzhniki (+ GrPP), HR, рекрутер, руководитель, глава подбора, 3–4 тестовых новичка с разными датами выхода, 120 синтетических ответов опросов для сводки. Все данные помечены как синтетические.
- Стартовая статья «Доступ к корпоративному порталу» — черновик HR с пометкой «ждёт подтверждения».

## 5. Дизайн

Ориентир — подход Apple, перенесённый в веб (скиллы `apple-design`, `mobile-native`, `emil-design-eng`, `ui-ux-pro-max`): интерфейс отвечает мгновенно, ведёт себя физически, ничего лишнего. Настроение — спокойный корпоративный, вызывающий доверие; тепло даёт тон Корсика в текстах, а не украшения.

### 5.1. Принципы
- **Простота, а не минимализм.** На каждом экране одно главное действие, второстепенное — на уровень глубже.
- **Привычность.** Паттерны iOS / «МАКС»: сгруппированные списки, нижние вкладки, листы снизу, «назад» слева сверху.
- **Мгновенный отклик.** Нажатие подсвечивается на касании (`:active`, `scale(0.97)`, 100 мс), загрузка дольше 300 мс — скелетон.
- **Wayfinding.** Каждый экран отвечает: где я, что здесь, куда дальше, как выйти.
- **Обратная связь четырёх видов:** статус, успех, предупреждение, ошибка — с иконкой и текстом, не только цветом.

### 5.2. Токены
| Токен | Светлая | Тёмная |
|---|---|---|
| `--bg` (фон экрана) | `#F2F2F7` | `#000000` |
| `--surface` (карточки, ячейки) | `#FFFFFF` | `#1C1C1E` |
| `--text` | `#111827` | `#F5F5F7` |
| `--text-secondary` | `#6B7280` | `#A1A1AA` |
| `--primary` (действия, ссылки) | `#2563EB` | `#3B82F6` |
| `--success` | `#16A34A` | `#22C55E` |
| `--warning` | `#D97706` | `#F59E0B` |
| `--danger` (красные флаги) | `#DC2626` | `#F87171` |
| `--separator` | `#E5E7EB` | `#2C2C2E` |

- Тема — по `prefers-color-scheme`. Контраст текста ≥ 4,5:1 в обеих темах.
- Отступы — шкала 4 / 8 / 12 / 16 / 24 / 32; радиусы — 10 (ячейки), 14 (карточки), 999 (чипы).
- Иконки — Lucide (SVG, одна толщина линии 1,75), без эмодзи в интерфейсе Mini App.

### 5.3. Типографика
- Системный шрифт (`system-ui`: SF на iOS, Roboto на Android) — кириллица и оптические размеры из коробки.
- Шкала: 13 (подписи) / 15 (вторичный) / 17 (основной) / 20 (заголовок раздела) / 28 (заголовок экрана).
- Трекинг по размеру: заголовки −0,02em, основной текст 0. Межстрочный: заголовки 1,15, текст 1,45.
- Иерархия — вес + размер: заголовки 600–700, текст 400, подписи 500. Цифры в таблицах — `tabular-nums`.
- Поля ввода — 16 px (без автозума на iOS); размеры в `rem`, чтобы уважать системный размер шрифта.

### 5.4. Экраны Mini App
**HR — нижняя панель из 4 вкладок** (иконка + подпись): «Новички», «Обращения» (бейдж с числом открытых), «База», «Ещё».

- **Новички:** поиск сверху; сгруппированный список по площадкам; ячейка — ФИО, «день N из M» с тонкой полосой прогресса, чипы-статусы (непройденный опрос, открытое обращение). Кнопка «+ Новичок» в шапке.
- **Карточка новичка:** шапка (ФИО, площадка, офис/производство, полоса прогресса испытательного) → секции «Ближайшие шаги», «Опросы», «Обращения», «Контакты (руководитель, рекрутер)».
- **Завести новичка:** сгруппированная форма с подписями над полями, `type="date"` для даты выхода, сегмент «Офис / Производство», выбор площадки и руководителя. После сохранения — лист снизу с QR, кнопками «Скопировать ссылку» и «Поделиться».
- **Обращения:** сегмент «Открытые / В работе / Закрытые»; карточка — категория (красный флаг — иконка и красная метка), площадка, день, первая строка цитаты, таймер срока. Экран обращения — лента сообщений как в чате, внизу закреплённое поле ответа (с учётом `safe-area`), над ним «Взять» / «Закрыть» и переключатель «Добавить ответ в базу» + выбор площадки.
- **База:** список документов (иконка типа, метка «КТ», дата версии), кнопка «Загрузить» → прогресс → итог «Готово: 42 фрагмента»; вкладка «Ответы HR»; загрузка xlsx сценария с отчётом по строкам.
- **Ещё:** «Частые темы» (горизонтальные столбцы с числами + таблица), «Демо» (сегмент перемотки −2 / 1 / 3 / 14 / 60 / конец, кнопка «Сформировать сводку»).

**Руководитель — один экран без вкладок:** «Мои новички» (ячейка: ФИО, день N, ближайшая встреча) → карточка с кнопкой «Провёл встречу». Пустое состояние — объяснение и что будет дальше.

### 5.5. Сообщения бота
- **Карточка ответа:** строка-подводка в тоне Корсика → цитата блоком (`> …`) → строка «Источник: ПВТР, п. 6.5.2, стр. 15» → кнопки «Открыть документ», «Связаться с HR».
- **«Не знаю»:** честная фраза + что будет дальше («передал HR, ответ придёт сюда») + кнопка «Задать другой вопрос».
- **Опросы:** один вопрос — одно сообщение; варианты кнопками в столбик, шкала 1–10 — две строки по 5; после ответа сообщение заменяется итогом (`POST /answers`), чтобы чат не захламлялся.
- **Красный флаг:** серьёзный тон без эмодзи, короткий текст «передал HR, увидит только HR» + телефоны ночью.
- Форматирование — markdown «МАКС», подписи кнопок короткие (до 30 знаков, лимит API 128).

### 5.6. Движение
- Библиотека — `motion` (Framer Motion) для React: пружины прерываемы и стартуют с текущего значения.
- Переходы между экранами — горизонтальный сдвиг «вперёд вправо / назад влево», пружина без отскока (`bounce 0`, `duration 0.35`).
- Листы снизу — тянутся пальцем 1:1, отпускание с учётом скорости (проекция импульса), лёгкий отскок (`bounce 0.15`); закрываются туда же, откуда пришли.
- Появление списков — короткий каскад 30 мс на элемент, только при первом показе.
- `prefers-reduced-motion` — вместо сдвигов и пружин короткое затухание 200 мс; `prefers-reduced-transparency` — плотные фоны вместо размытия.
- Шапка и нижняя панель — полупрозрачный материал (`backdrop-filter: blur(20px) saturate(180%)`), контент прокручивается под ними.

### 5.7. Мобильная база
- `viewport`: `width=device-width, initial-scale=1, viewport-fit=cover, interactive-widget=resizes-content` (без запрета зума).
- Высота приложения — `100dvh`; отступы `env(safe-area-inset-*)` для шапки, нижней панели и поля ввода.
- `-webkit-tap-highlight-color: transparent`, `touch-action: manipulation` на кнопках, `:hover` только внутри `@media (hover: hover) and (pointer: fine)`.
- Цели касания ≥ 44 × 44, расстояние между ними ≥ 8.
- Проверка на реальном телефоне внутри «МАКС» (iOS и Android), а не только в эмуляторе.

### 5.8. Картинка еженедельной сводки
Формат 1080 × 1350: заголовок с датами недели → три KPI-карточки (новички, средняя оценка, открытые сигналы) → столбцы настроения по площадкам → топ-3 темы с числом упоминаний → строка «мало данных» для мелких площадок. Те же токены и шрифт, светлая тема.

## 7. Деплой

**Локальная разработка — тоже в Docker Compose** (Docker Desktop, Apple Silicon / arm64):
- `docker compose up` поднимает `postgres` (pgvector), `app` (бот + планировщик + API, код смонтирован томом, автоперезапуск при изменениях) и `miniapp` (Vite dev-server с hot-reload);
- миграции, заполнение демо-данных, импорт сценария и оценка качества — командами `docker compose exec app …` (обёртки в `Makefile`);
- модель `bge-m3` скачивается один раз в именованный том, чтобы не тянуть её при каждой сборке.

**Сервер:**

- VPS с Docker Compose: `postgres` (образ pgvector), `app`, `caddy`.
- Caddy выдаёт HTTPS для Mini App и API. URL Mini App прописывается в настройках тестового бота.
- Бот работает через long polling.
- Секреты — в `.env` на сервере, в репозитории только `.env.example`.

## 8. Порядок сборки

1. **Каркас:** репозиторий, Docker Compose, Postgres + миграции, бот отвечает на `/start` с кодом и привязывает пользователя, согласие и «ты/вы».
2. **Сценарий:** импорт xlsx, планировщик, отправка шагов с кнопками и картинками, машина времени. Проверка на двух площадках.
3. **Ответы:** нарезка и индексация документов, поиск, маршрут вопроса, карточка ответа, «не знаю → HR».
4. **Обращения и Mini App HR:** тикеты, ретрансляция ответа в чат, HR-группа, экраны «Новички» и «Обращения», вход по `initData`, ответы HR в базу.
5. **Опросы и сигналы:** движок опросов, «что мешает?», напоминания, правила флагов, разбор LLM.
6. **Руководитель и сводка:** push «проведи встречу», экран руководителя, еженедельная сводка картинкой.
7. **Загрузка документов и xlsx** из Mini App.
8. **Качество и демо:** скрипт оценки, демо-данные, прогон сценария демо, запись видео-страховки.
9. **Бонусы** (раздел 9).

## 9. Бонусы (после основы)

| Бонус | Как сделать |
|---|---|
| «Открыть документ» с подсветкой пункта | Экран Mini App: текст документа из `kb_chunks`, прокрутка и подсветка цитируемого пункта по `chunk_id` из кнопки |
| «Ты спрашивал про … — вот ответ» | При публикации ответа HR в базу найти в `questions_log` похожие неотвеченные вопросы и разослать ответ их авторам |
| Аудит сценария | Проверки при импорте xlsx: промежутки без опросов, шаги без действия, руководитель без касаний → отчёт в Mini App |
| «Вторая площадка за 5 минут» | Загрузка xlsx с новым тегом площадки → тестовый новичок с её кодом получает её шаги (опирается на импорт и машину времени) |
| Пульс «совпало ли с обещанным?» | Две новые строки сценария: 7-й день и 5-я неделя |
| Кривая настроения и флаг падения оценок | Линия «неделя × площадка» в сводке; правило: падение на ≥ 3 пункта → жёлтый флаг |
| Подсказки «Спроси меня про…» | Кнопки-темы под приветствием и после «не знаю» из отвечаемых вопросов эталона |
